# r-ai-image

A template for AI image posts. Based on CFW Social's built-in AI image recipe.

## 1. What it makes

One image, or a batch of 2, 3, 4 or 6, as PNG files at an exact canvas: 1080x1080 (default),
1080x1920 or 1920x1080. A contact sheet of the batch and a quality report come with it.
Images are generated by Kie (kie.ai) from a text prompt, or from a reference image the user supplies.

This is a template to learn from and adapt. The plan is that a brand's bot reads it, builds its
own recipe, and saves that recipe in the brand's recipe library in CFW Social, which then runs
it. The CFW tools for saving a recipe are live, for a key made with the "Save its own recipes"
permission (see [../../docs/DESIGN.md](../../docs/DESIGN.md)). You can also read the steps and follow
them by hand or with your own agent.

## 2. What you need

| Tool | Version run |
| --- | --- |
| Python 3 | 3.15.2 |
| ffmpeg and ffprobe | 8.1 |
| bash | 5.3.12 (the shell tests also ran macOS `/bin/bash` 3.2.57 and zsh) |

Other versions are untested. ffmpeg also tiles the contact sheet and re-splits the batch, so no
other image tool is needed.

**Provider account:** a Kie account with credits. The bot uses the brand's own Kie key from the
order. It reaches `b-kie-ai` as a per-command prefix `KIE_AI_API_KEY="${KEY:-}"` on the one
`generate.py` command, or on standard input; no other command has it. The recipe never reads a key from a file, never writes it into a
file and never prints it. Every generated image spends that account's credits (check Kie's current
prices for `z-image` and `gpt-image-2-image-to-image`). Nothing here has been run against a real
Kie account: see section 10.

A vision-capable model must look at every image: the look questions of the quality gate are
answered by the bot's own vision, and a person can read the scorecard.

## 3. Blocks it uses

| Block | Why | Path |
| --- | --- | --- |
| `b-kie-ai` | `scripts/generate.py` makes one image through the Kie API per call, text-to-image or (with `--ref`) image-to-image, and saves a checked PNG | `../../blocks/b-kie-ai/` |
| `b-qa-gate` | `check.py --kind image` runs the mechanical checks in `acceptance.json` and writes a scorecard; `--finalize` records the answers to the look questions | `../../blocks/b-qa-gate/` |

Read the two blocks' own README files before running this recipe. They are the interface. The
steps call them by the relative path `../../blocks/b-<name>/`, so the recipe sits two folders
below the folder that holds `blocks/`.

## 4. The steps

```text
prompt, count, shape, [reference image]
   |
   v
01 plan prompts ---> 02 generate ---------> 03 quality gate + looks
  prompts.json        (b-kie-ai)              (b-qa-gate)
                      image_1.png             final.png
                      contact_sheet.png       qa_report.json
                      images.json
```

Each step has its own file in `steps/`. `steps/_shared.md` holds the rules every step shares.
Step 01 writes one prompt per image. Step 02 writes each prompt to a file and calls
`../../blocks/b-kie-ai/scripts/generate.py` once per image (text-to-image with `z-image`, or
image-to-image with `gpt-image-2-image-to-image`), fits each result to the exact canvas with
ffmpeg and tiles a contact sheet. The generation command is:

```text
KIE_AI_API_KEY="${KEY:-}" python3 "$GEN" --prompt-file work/prompt-N.txt --out work/raw-N.png --aspect "$AR" --timeout 240 --poll 5
```

where `GEN` is `$BLOCKS_DIR/b-kie-ai/scripts/generate.py` (`BLOCKS_DIR` is `$RECIPE_DIR/../../blocks`),
and the command is prefixed with `KIE_AI_API_KEY="${KEY:-}"` so the key is on that command only. With a reference image the command adds `--model
gpt-image-2-image-to-image --resolution 2K --ref work/ref-in.jpg`. The block never repeats a paid
call, and this recipe adds no automatic retry. Step 03 re-splits the batch, runs `b-qa-gate`
(`check.py --kind image`) on every image, lists the look questions, has the bot answer each one by
looking at the image, records the answers with `check.py --finalize`, and picks the final.

## 5. Inputs and outputs

| Input | Required | Values |
| --- | --- | --- |
| `prompt` | yes | The image description in plain text. |
| `count` | no | `1` (default), `2`, `3`, `4` or `6`. |
| `aspect_ratio` | no | `1:1` (default), `9:16` or `16:9`. |
| `reference_image` | no | A picture to base the images on (PNG, JPEG or WEBP, 10 MB or less after step 02 shrinks it to 2048 px a side). |

Plus a `brief.json` with the brand's name, palette and an optional `imageStyle` prompt template.

| Output | From | What |
| --- | --- | --- |
| `prompts.json` | 01 | One prompt per image, a negative list, the model (`z-image`, or `gpt-image-2-image-to-image` with a reference). |
| `image_1.png`, `contact_sheet.png`, `images.json` | 02 | The first image, the whole batch tiled, the batch description (size, model, task ids, attempts). |
| `final.png`, `qa_report.json` | 03 | The chosen image and, per image, the verdict and every row of its final scorecard. |

The saves carry a preview and the report. For a batch, keep every passing full-resolution image
(`work/img-N.png`, in prompt order) as the real delivery: `final.png` and the contact sheet are not it.

## 6. Network use

This matches the README of `b-kie-ai`. `b-qa-gate` contacts nothing, and steps 01 and 03 make no
network call.

| When | Host | What is sent |
|---|---|---|
| Setup | none | Nothing. There is nothing to install beyond the tools in section 2. |
| Run (step 02) | `api.kie.ai` | The create call and the status checks, with the key. |
| Run (step 02), only when a reference image is used | `kieai.redpandaai.co` (Kie's documented upload host) | The reference image, with the key. Kie's docs say it is deleted after 24 hours. |
| Run (step 02) | the https host Kie names in its reply for the result file | A plain download with no key header. The host is chosen by Kie. The key is never sent to it. |

A reference image is uploaded to Kie. Do not use one you may not send to Kie.

## 7. Run the tests

From this folder. They need no network, no real key and no paid account. A small fake Kie server
runs on `127.0.0.1`.

```sh
python3 -I test/test_blocks_flow.py -v
python3 -I test/test_image_steps.py -v
```

They need `ffmpeg` and `ffprobe` on the path, and the blocks `b-kie-ai` and `b-qa-gate`
in `../../blocks/`. Results: `test_blocks_flow.py` 20 tests, `test_image_steps.py` 3 tests, all pass.

- `test_blocks_flow.py` runs the steps' own code blocks with the real `generate.py` (through the
  documented command line; only the test-only server options are added by a stand-in file) and the
  real `check.py`: text-to-image and reference runs, a portrait batch, the gate with look answers
  and `--finalize`, a "no" answer, a flat image, a failed task that is not repeated, no key, a
  server that echoes the key, that the key value is in no output file, stdout or stderr, that only the `generate.py` command sees it in its environment, and that `ONLY` must be digits. It also
  checks step 01's own self-check (prompt length, the two models, the reference rule).
- `test_image_steps.py` checks the ffmpeg contact sheet for every count and the re-split of the batch, in bash, macOS bash 3.2 and zsh.

## 8. Sample

There is none. A sample needs a Kie account with credits (one `z-image` image at `1:1`) and a
vision-capable model to answer the look questions. To make one, give the steps a small order, set
`KEY` to your own key in the shell that runs the steps (not exported), and keep the saved `final.png`.

## 9. Terms used by CFW Social

A few names in this folder belong to CFW Social's order format. If you use this template outside
CFW Social, you can ignore them.

- **`manifest.json`**: the order format: inputs, steps, saves and checks. The `needs` block lists
  tools, engines and providers; it is a declaration, not a record of a tested run.
- **Engine** (`codex`, `claude-code` in the manifest): the kind of bot that runs the steps.
- **Check ids** such as `prompts_shape`, `image_dims`, `not_black`, `vision_qa_pass` and
  `final_dims`: the names under which `manifest.json` declares each step's checks. Each step file
  says what to check; the id is just a label.
- **`saves`**: the files a step hands on. **`canAsk`**: the one input a step may ask the user for.
- **`needs_input.json`**: how a step asks. **`brief.json`**: the brand and settings for an order.
- **Runner**: whatever executes the steps and records each check. This template adds none.

## 10. Limits and known gaps

- Only Kie is supported, and only the two models `b-kie-ai` confirms from Kie's documentation:
  `z-image` (text-to-image, prompt up to 1000 characters including the negative list) and
  `gpt-image-2-image-to-image` (with a reference). Other Kie models, and other providers, are not
  part of this recipe. Model names, prices and allowed values are Kie's and change.
- **Not proven with a real Kie account.** Nothing here has run against live Kie. The tests use a fake
  server. `b-kie-ai` says the same.
- Every aspect ratio this recipe offers (`1:1`, `9:16`, `16:9`) is allowed by both models. Kie
  returns its own size, so step 02 scales and centre-crops each result to the exact canvas.
- No automatic retry. A failed or timed-out task may still be charged; a regeneration is a new
  paid call and needs the user's say-so.
- `b-qa-gate` measures size, a black frame and a flat frame. The five look questions are answered
  by the bot's own vision. A scorecard is a record, not proof: it does not prove the bot looked.
- The manifest declares one final image only. A batch needs the passing `work/img-N.png` files kept
  and delivered by the bot; the manifest has no per-image delivery save.
- `acceptance.json` names the square canvas; step 03 adjusts a copy for 9:16 and 16:9.
- The steps use bash arithmetic loops and are written for a Unix-style shell. This edition was run
  only on macOS 26.5 (Apple silicon, arm64), with the tool versions in section 2. The manifest lists
  `macos` under `needs.os` because of that; it says nothing about other systems.
- Not proven on any particular bot app or operating system: this folder holds no recorded run.
- The two blocks have been tested with this recipe only against the fake server. Read their scripts
  before running them.
